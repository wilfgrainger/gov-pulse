# public-data.org 1.0.0

## Release intent

Version 1.0.0 is the first release contract for the current public-data.org architecture. It establishes a request-time web Worker as the normal application plane, a three-route data Worker as the only public runtime data contract, and a bounded Cloudflare Pages seed/fallback.

## Included guarantees

- National publication fragments are scoped to their run ID, so overlapping or late Queue retries cannot mix evidence from different runs.
- The finaliser publishes only current source-owned fragments and records an exact degraded-section manifest when required evidence is missing.
- International comparison publication is isolated from national readiness and is unavailable after its seven-day evidence window expires.
- YouGov discovery is restricted to approved HTTPS publisher hosts, downloaded archive and PDF decompression is bounded, and the Pages seed is restricted to the exact configured Pages object.
- The public national response cache cannot outlive the currentness deadline and the international response cache is capped at the same deadline.
- Evidence-bearing UI exposes publication state, a complete financial time-series table, accessible share failures, source-specific dates and caveats, and avoids composite comparison judgments.
- Production deployment is allowed only from `main`, uses immutable GitHub Action references, audits production dependencies, deploys data and bootstrap before the reader-facing web Worker, and verifies the exact Worker version tag.
- The source and data licensing boundary is explicit: application code is Apache-2.0, while publisher and dataset terms remain authoritative.

## Release gates

The release candidate is not considered production-observed merely because its source tests or build pass. Handoff records must keep these claims separate:

| Gate | Required evidence |
| --- | --- |
| Source correctness | focused falsifying tests, full Vitest/Worker suite, lint and architecture guards |
| Artifact correctness | deterministic Pages seed build and pinned OpenNext request-time Worker build |
| Browser correctness | deterministic desktop and mobile journeys against the local application server, with the OpenNext artifact built separately |
| Repository state | exact local head, clean intended diff, remote head and PR checks |
| Cloudflare publication | deployed data Worker revision, Queue/bootstrap completion, national and comparison route responses |
| Production observation | request-time HTML, health, snapshot, comparison and affected user journey observed at the exact deployed head |
| Operations | bounded scheduled run evidence, alert path and exercised rollback |

Until the last four rows are observed in the target environment, this document describes a verified release candidate rather than a claim that public production is healthy.
